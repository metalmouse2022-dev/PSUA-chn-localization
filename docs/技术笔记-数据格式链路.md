> 本文记录当时对本地 CHD 输入的格式分析结果。不是全部结论都经过实机验证；“已验证”指工程日志中对应的本地样本/模拟器检查，具体内容和版本需复核。CVM/NBL 关键脚本因上游许可不明而暂未随本仓库发布，因此该链路不能单凭公开快照完整复现。见[来源与发布清单](来源与发布清单.md)。

## 1. CVM (CRI ROFS)

- chunk 结构：`[4CC:4][BE64 len:8][data]`；CVMH 头 0x7F4@0x00C，ZONE@0x800。
- 关键字段（大端）：文件大小@0x1C(BE64)、flags@0x30（**0x10=TOC加密**）、numEntries@0x80、isoStartSector@0x88、sectorTable@0x100；ZONE 内 datalocISO = (sector@0x82C, length@0x830)。
- 扇区映射：物理扇区 = ISO逻辑扇区 + isoStartSector(=3)；解密种子 = ISO逻辑扇区 + datocISO.sector - isoStartSector(=0)。
- 加密只作用于 TOC（PVD 扇区16 到目录树末尾），数据扇区明文。
- 密钥派生：CalcKeyFromString(密码) —— 质数表哈希（`scripts/rofs_crypt.py` 精确移植，保持 C 语义 32 位回绕）。
- **本作密码 `4147a5c2b5fe0357`**（来自 PSU_ERX.elf 数据区 VA 0x5667D0，挂载函数 0x4710 由 [0x5FA1AC] 间接传入）→ 密钥 `40 b7 5f 35 53 47 4f 63`。
- 工具：`scripts/cvm_extract.py`（解包）；重建流程待做（cvm_header.bin 已备份头部 3 扇区）。

## 2. NBL (NMLL/TMLL)

- 头 0x30B（NMLL）小端：version@4（2=PRS/0x800对齐；0x1002=deflate/0x40对齐）、headerSize@8、numFiles@C、uncompSize@10、compSize@14、pointerLen@18、**decryptKey@1C**、TMLL 信息@20-2C。
- 文件表：0x30 + 0x60×i，每项 = ident(4)+chunkSize(4)+unk(8) + **0x30B Blewfish 加密**{文件名[0x20] SJIS, position u32, size u32, ptrPos u32, ptrSize u32} + subHeader(0x20)。
- 数据区 @ (headerSize+0x7FF)&~0x7FF：v2 整块先 Blewfish 解密再 PRS 解压到 uncompSize。
- 指针区 @ (dataLoc+size+0x7FF)&~0x7FF（i32 数组，游戏内重定位用，回写时需保持）。
- 工具：`scripts/nbl.py`。

## 3. SEGA Blewfish 变体 (`scripts/blewfish.py`)

- 密钥为单个 u32，**XOR 进全部 18 个 P 盒项**（非标准 Blowfish 密钥调度），再标准自链生成。
- F 函数：`((S0[t0] + S1[t1]) ^ S2[t2]) + S3[t3]`，t = b 的 LE 字节，**子盒偏移 256/512/768**（移植时漏偏移是本次最大的坑，用 PowerShell Add-Type 编译原版 C# 对照追踪定位）。
- ECB 逐 8 字节，字内 LE（NMLL）。

## 4. PRS (Legacy 变体, `scripts/prs.py`)

- 控制位 LSB-first；1=字面量；0+1=长拷贝（2B：raw=0 为 EOF；size=raw&7（0 时读扩展字节 **+1**）；back=8192-(sext16(raw)>>3 & 0x1FFF)）；0+0=短拷贝（2 位长度 2..5 + 1B back=256-b）。
- 本工具头注早期误写 Modern(+10)；实际实现和自造样例采用 Legacy(+1) 语义。本地游戏样本验收应使用匹配版本输入。

## 5. 文本格式

- **UTF-16LE**，NUL(u0000) 终止；文件头 u32[0]=文件总大小，随后偏移表指向各串。
- 核心文件（GA_TEXT_J.NBL 内）：WindowText(1203串)、ItemGeneral(726)、DungeonLobby(130)、EnemyText(134)、PlayerText(80) 等 16 个。
- 角色台词（GA_APC_WORDS_J.NBL 内）：Words_aXX_{角色}_J.bin × 72（Ethan/Hyuga/Karen/Lumia...）。
- 合计 ~10,240 串 / 96,901 字符（战斗与系统层；主线剧情文本位置待查）。
- 语言后缀：_J 日文；另有 _AE/_F/_G 等多语言版本文件（PSU 国际化遗留）。

- **容器与位置**：`GA_TITLE.NBL` 偏移 `0x20000` 处的 TMLL 纹理块内：
  * 条目 #118 为 `ad_text01.svr`（主菜单选项，偏移 3,155,584，32,832 字节）。
  * 条目 #17 为 `ad_title_select01.svr`（开机副标题与白线，偏移 830,720，32,832 字节）。

## 9. 道具与装备说明容器 (`XF_ITEMEXPLANETEX_J.AFS`)

- **容器规模**：`XF_ITEMEXPLANETEX_J.AFS`（17.7 MB），MiniAFS 格式，共 4,286 项（4,285 项 NBL 归档 + 1 项末尾文件名表）。
- **条目内容**：项 0..4284 每个条目均为独立 NBL，内含单文件 `atk.k`（标准 TextFile 结构，UTF-16LE 字符串）。去重后共 2,573 条唯一说明。
- **单字符串文件的检测坑**：`atk.k` 内仅包含 1 个字符串偏移，原 `scan_all_text.py` 循环遍历要求至少 3 个偏移检验导致其被误判跳过。单字符串文本文件需按 `count = (size_of_table) // 4` 判定。
- **零重定位风险**：所有 4,285 个说明项内部 `pointer_size = 0`，不含内部/跨文件指针重定位，增删字长重建零风险。
- **末尾文件名表**：第 4285 项为 205,680 字节的 AFS 描述符表（每项 48 字节：32 字节文件名如 `0_J.nbl` + 16 字节时间戳/大小），打包时必须作为最后一个数据项保留。

## 任务/房间 AFS 多语言结构（重扫后确认）

- 每个任务 AFS 单元 = N 个分块 × 10 语言条目；**日文 = 每块第 1 个**（#00/#10/#20/...），繁中在 #x9；XF_MYROOM.AFS 例外：10 语言连续排列（JP=#07），CS/CT/S 条目为空壳（无官方中文）
- 判日文条目的可靠方法 = **内容检测**（子树内文本含假名），比 #x0 序号模式稳（不同 AFS 排布不一）
- 旧 scan_all_text 自带 parse_afs 有两个坑：①MiniAFS count=末条索引（实际 count+1 对）②count 为奇数时 n%2 校验直接放弃解析 → XF_MYROOM(count=11) 整体漏扫；已改用 afs.py 修复版

## NBL 指针表真正语义（v6 取证，房间门 bug 终极根因）

参考 tools/psu_ae_src RawFile.RebaseFile / NblLoader：
- NBL 头表里的 pointerPosition/pointerSize 定位**指针表数组**（blob 末尾独立区）
- **指针表数组里的值不是指针，是"位置"**——指出真指针藏在哪个文件数据内的哪个偏移（blob 绝对地址，`位置 - fileOffset` = 文件内偏移）
- **真指针是文件数据里内嵌的 u32**（blob 绝对目标地址），通常指向本文件内部（quest NBL 305 万处），
  少数跨文件：STORY14_A_0 / STORY19_A_0 的 quest.snr 内嵌指针指向同 NBL 内 text.bin 的 0x0/0x4（基址）
- 文件挪动 delta 时必须两处同步 +=delta：①表里的位置值 ②数据内嵌的 u32。
  nbl.py 旧版只做①——v3/v5 第一次移动条目即触发，内嵌指针全体悬空 → quest.snr 拿到悬空 text.bin 基址 →
  任务系统初始化失败 → 房间门（任务系统对象）消失。v4 就地替换 delta=0 从不触发所以正常。
- **规则**：跨文件内嵌指针指向的 text 容器必须就地替换（trans_import.find_pinned_texts 自动检测钉住）；
  其余 text 容器可全量重建（nbl.py 修复后同文件指针自动重定位正确）
- 间隙指针 420 处（指向条目间 padding）+ 恰在 quest.snr 末尾 340 处：v4 实证无害（非承载）

### 上述指针语义已实机验证（v6，2026-10-25）

**修改 NBL 内条目布局的正确姿势**（nbl.py save() 已实现）：
1. 每文件按序拼接、0x20 对齐，delta = 新位置 − 旧位置
2. 指针表数组值 += delta（它们是"内嵌指针的存放位置"）
3. **文件数据内嵌 u32 += delta**（在 e.data 的 `表值 − 旧position` 偏移处，有符号 int32）——旧版漏掉这步 = v3/v5 门 bug
4. 例外：跨文件内嵌指针（quest.snr → 同 NBL 内 text.bin 基址@0x0/0x4）无法按属主 delta 修正，
   其目标 text.bin 必须保持字节布局不变（trans_import.find_pinned_texts 自动钉住 → 就地替换）

**验证标准**（validate_v5.py）：
- 外语/数据条目：字节级等价
- 钉住容器：**布局等价**（size/T/tbl/descs 不变），槽内译文字节可变（指针目标=文件头不受影响）
- 全部内嵌指针：位置落在属主文件内、目标落在 blob 内（0 异常)
- PUA 占位符：逐串比对（\uF820/\uF620-23/\uF600 丢失即弃用该译文）

**测试方法论**：任何改动 NBL 布局的代码，回归测试必须包含 delta≠0 场景
（拉长前面条目 → 断言后续文件指针表值与内嵌值同步平移），仅做原样回环（delta=0）等于没测重定位。

  * 补丁脚本：`scripts/patch_apc_text.py`，同步回填 `ApcText_J.bin`、`ApcText_CS.bin`、`ApcText_CT.bin`。

- **关卡区域横幅标题 (`unit_title_*.bin`)**：
  * **作用域**：进入副本关卡时顶部弹出的横条地图标题（如 `米兹拉基保护区：区块D-1`）。
  * **存放位置**：存放在各个任务 AFS（`XF_QE_*.AFS`、`FA_QE_*.AFS`）的 0 号条目中（每个关卡区块对应一个独立文件，如 `unit_title_01.bin`～`unit_title_06.bin`）。
