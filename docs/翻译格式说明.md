# 翻译格式说明（AI 翻译工作指南）

> **校验范围**：`trans_validate.py` 可检查它所读取的译文数据中的格式符和字符范围；它不会把 `#`、`>`、`=` 行与对应原始导出逐项比对，也不会证明编号、条目顺序和原文完整。交付前还需对照同一版原始导出基线检查这些结构字段。

> 本文档面向执行翻译的 AI / 译者。请先完整阅读，再开始翻译 txt 文件。

## 工作对象

`work/translation/` 目录下按类别分好的 `.txt` 文件（每文件约 300 条）。每个条目为 4 行 + 1 空行：

```
# 00042 [窗口/菜单] @GA_TEXT_J.NBL/WindowText_J.bin:12
> キャンセル
< 取消

```

- `#` 行：**禁止修改**。内容为全局编号、上下文提示、来源（容器路径:条目索引，仅供理解）。
- `>` 行：日文原文。**禁止修改**，仅作对照。
- `=` 行（可选）：**官方繁体中文参考**（游戏自带的多语言数据）。**禁止修改、禁止删除**；可繁转简后微调作为译文。没有此行的条目自行从日文翻译。
- `<` 行：中文译文。**你只改这一行**。留空 = 不翻译（游戏回退显示日文）。
- 块之间空行分隔。不要增删条目、调换顺序、新建文件。

## 转义规则（重要）

原文中的特殊字符已转义，译文请使用相同转义：

| 转义 | 含义 | 译文处理 |
|---|---|---|
| `\n` | 换行（UI 排版换行） | 按排版需要保留或调整数量 |
| `\\` | 反斜杠本身 | 保留 |
| `%s` `%d` `%05d` 等 | 程序格式符 | **必须原样保留，数量与顺序不可变** |

示例：
```
> ID:%s%d\n使いますか？
< ID:%s%d\n要使用吗？
```

## 硬性规则

1. **格式符完整保留**：含 `%s`/`%d`/`%f`/`%%` 的句子，译文必须含相同数量、相同顺序的格式符（`纠错脚本`会强制检查）。
2. **字符集限制**：译文用字必须在 GB2312 一级字库（3755 常用字）内，另可使用：日文假名、原字库已有汉字、常用全角标点（，。！？、：；「」『』（）…—・～）。**不要用生僻字、繁体字、emoji**。拿不准就换常用字（例：「臉」→「脸」）。
3. **纯 ASCII/数字/符号串不译**：原文只有数字、符号、英文代码（如 `OK`、`A`、`Lv.%d`）时，译文保持原样（可以填 `< OK`）。
4. **长度参考**：
   - 菜单项/按钮：≤ 6 个汉字为宜（原文多为 2~6 假名）
   - 道具/技能名：≤ 10 个汉字
   - 说明文/对话：自由，但约为原文的 60%~110%（中文通常比日文短）
   - 带 `\n` 的说明文：保持相近行数，单行 ≤ 20 汉字
5. **语气与称谓**：
   - 系统消息用「～了」「～吗？」等简洁书面语
   - 角色台词保持原作语气（粗豪/温柔/机械等），参照名词规范中的角色表
   - 游戏文本中「！」「？」用全角
6. **专有名词**：一律按 [名词规范.md](名词规范.md) 翻译；规范未收录的，首次出现时选简洁译名并保持全文一致。
7. **不翻译的内容**：原文为空的条目保持空；测试串/占位串（如 `あああ`）可保持原样。

## 交付要求

- 保持原文件名、条目编号与顺序，不要增删条目。
- 翻译完成后运行：`python scripts/trans_validate.py work/translation`，按报告修正全部错误后再交付（退出码 0 = 通过）。
- 部分翻译也可交付（未翻条目回退日文），但请保证已翻部分通过校验。
- 专有名词以 [名词规范.md](名词规范.md) 为准；角色台词注意语气一致。
