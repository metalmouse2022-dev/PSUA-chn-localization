## 解包链

```
PSUA(jap).chd
  └─ chdman extractcd → PSUA.bin + PSUA.cue   (work/original/)
       CUE: TRACK 01 MODE1/2048  → bin 即 2048B/扇区 ISO
       PSUA.iso = PSUA.bin 的硬链接（同盘不占空间）
```

- 注意：chdman info 显示 unit 2448 是 CHD 内部含子通道编码；extractcd 输出已剥离为 2048 用户数据。`scripts/bin2iso.py` 留作 2352 raw bin 的后备转换器。

## PSUROFS.CVM 头部（0x00–0x5F）

```
00: "CVMH" 00000000
0C: 000007F4   ← 头部相关长度/版本字段（待定）
20: BE2FC800 6B070D11 39092400   ← 时间戳/校验（待定）
30: "ROFSROFS"
38: "BLD Ver.1.52 2003-06-09"
```

- 前 64KB 内**无** `CD001` → 不是简单的"0x800 偏移 ISO9660"，是 CRI ROFS 1.52 私有格式。
- ROFS 目录/数据布局需要专门解析（quickbms `cri_rofs.bms` 或参考已有实现自研 Python 解析器）。

## CDPSU0.AFS 头部

```
00: "AFS\0" 11000000  → 17 个条目
08: 偏移表（8 字节步进，值如 0x05084000 等大偏移，需验证是否加扰）
```
标准 CRI AFS。条目内容类型（ADX/其他）待抽样确认。

## 待验证问题清单

1. CVM 的 ROFS 1.52 目录结构（节点格式、是否加密/加扰）
2. CVM 内文本文件的编码（PS2 日文游戏通常是 Shift-JIS 或自定义双字节表）
3. 字体贴图格式（PSU 系列多为贴图字库，需定位并重绘）
4. CDPSU0.AFS 是否为语音（若是 ADX 音频则不影响文本汉化）
5. ELF 内部是否有用于文本渲染的宽度表 / 编码转换表
